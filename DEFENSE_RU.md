## Как устроен проект

`Graph` хранит список логических рёбер и списки смежности. В неориентированном графе ребро присутствует в двух списках смежности, но сортируется Kruskal один раз. Петля тоже имеет две записи смежности и не попадает в остов. Кратные рёбра разрешены. `indegree` поддерживается при добавлении рёбер; Kahn получает копию, поэтому алгоритмы не изменяют граф.

DSU хранит `parent[]`, `size[]` и количество компонент. `find` сначала ищет корень, затем вторым циклом направляет весь пройденный путь прямо в корень. `union` присоединяет меньшее дерево к большему. Сжатие путей и объединение по размеру вместе дают амортизированную сложность `O(alpha(n))`; это не гарантия `O(1)` для каждого отдельного вызова. Две вершины в одной компоненте, если их корни совпадают.

Kruskal сортирует рёбра по весу собственной стабильной merge sort. Проверка `union(u,v)` сама вызывает два `find` и добавляет ребро только при разных корнях. Когда остаётся одна компонента, поиск прекращается; в несвязном графе придётся просмотреть все рёбра. Результат — лес из `n-components` рёбер. Сортировка оплачивается полностью даже при раннем завершении.

Prim начинает с 0, достаёт минимальное ребро из `PriorityQueue` и пропускает его, если конечная вершина уже посещена. После исчерпания очереди начинает следующую непосещённую компоненту. Это lazy-версия: в очереди могут оставаться устаревшие кандидаты. Для мультиграфа её граница — `O(n + m log m)`, память `O(n+m)`. Для простого графа `log m = O(log n)`, но при произвольном количестве параллельных рёбер так автоматически говорить нельзя.

Kosaraju сначала записывает вершину при **выходе** из DFS. В каждой явной рамке важен индекс следующего ребра: если сразу записать вершину при входе, порядок будет неправильным. Потом строится обратный граф и вершины обходятся в обратном порядке завершения. Каждое новое дерево второго прохода — одна SCC. Два прохода смотрят ровно `2m` рёбер; создание обратного графа — ещё `m` подготовительных просмотров.

Kahn добавляет в очередь все вершины с входящей степенью 0. При извлечении вершины уменьшает степени её соседей. Если извлечено меньше `n` вершин, есть цикл: частичный список нельзя выдавать за топологический порядок. Проверка результата строит `pos[]` и требует `pos[u] < pos[v]` для каждого ребра.

Кратчайшие пути в DAG начинаются **со всех** вершин с indegree 0, их расстояние — 0; остальные сначала имеют бесконечность. Для каждой вершины в топологическом порядке выполняется `d[v] = min(d[v], d[u]+w)`. Все её предшественники уже обработаны, поэтому второго прохода не нужно. Отрицательные веса допустимы: направленных циклов нет. В обычном графе отрицательный цикл может делать кратчайший маршрут неограниченно отрицательным; даже без такого цикла отрицательные рёбра могут нарушить жадный выбор Dijkstra.

`parent[]` хранит предыдущую вершину, `parentWeight[]` — вес конкретного выбранного ребра. Последнее важно при параллельных рёбрах разных весов. Суммы и расстояния имеют тип `long`: цепочка рёбер с допустимыми `int`-весами может переполнить `int`.

## Как обосновать корректность

Для MST используй свойство разреза: если добавить минимальное пересекающее разрез ребро в оптимальное дерево, возникает цикл; другое пересекающее разрез ребро в цикле не легче. Его можно заменить без увеличения веса. Kruskal применяет это к компонентам DSU, Prim — к границе посещённого множества. Равные веса могут давать разные деревья одинакового веса.

Для DAG используй индукцию по топологическому порядку: последний шаг любого пути в вершину идёт из более ранней вершины. Её оптимальное расстояние уже известно, и мы рассматриваем все такие последние рёбра. Поэтому после обработки предшественников расстояние окончательное.

## Что показывают счётчики

- `dsu_ops` — вызовы `find` плюс **успешные** объединения. Для Kruskal: `2k + (n-c)`, где `k` — реально рассмотренные рёбра, `c` — итоговое число компонент.
- `edge_scans` — просмотры в основном проходе: Prim `2m`, Kosaraju `2m`, Kahn `m`, релаксации DAG `m`.
- `comparisons` — сравнения весов сортировки/кучи, а у DAG сравнения кандидата расстояния с текущим расстоянием.
- `max_depth` — максимальная глубина собственного стека. Для Tarjan берётся максимум из глубин двух его стеков. Очередь Kahn не является DFS-стеком.
- `preparationEdgeScans` отдельно учитывает построение транспонированного графа и внутренний Kahn для DAG. Они входят во время исполнения, но не в предписанный CSV-счётчик прохода.

Покажи `results/analysis.csv`. У линейных обходов slope просмотров равен 1.000. Логарифмический множитель Kruskal проявляется в сравнении весов при сортировке, а не в `edgeScans`: нельзя честно утверждать, что Kruskal просматривает `m log m` рёбер. Из-за ранней остановки отношение `edgeScans/m` меняется. Таблица отчёта нормирует суммарные операции MST на `m log2 m`, а просмотры обходов — на `n+m`.

Данные `m=4n` и `m=20n` обе имеют линейное число рёбер относительно n. «Dense» в PDF — относительная плотность, не `Theta(n^2)`. Для действительно плотного простого графа матричный Prim за `O(n^2)` может быть разумнее; в задании реализован обязательный вариант с очередью.

## Бонусы

Tarjan использует `index[]`, `low[]`, стек рамок DFS и стек активных вершин. Ребро к активному предку уменьшает `low[v]` через `index[to]`, а завершившийся ребёнок передаёт `low[child]` родителю. Если `low[v]==index[v]`, снимаем активные вершины до v включительно: это одна SCC. Рёбра в уже закрытые SCC не меняют low-link. Ровно `m` просмотров вместо двух проходов Kosaraju; транспонирование не требуется.

В конденсации каждая SCC превращается в вершину. Межкомпонентные рёбра сохраняют веса; параллельные рёбра сохраняются. Если бы между компонентами был цикл, они были бы взаимно достижимы и составляли бы одну SCC. Значит, конденсация — DAG. Самый длинный путь считается заменой `min` на `max`; это эквивалентно смене знака веса и решению кратчайшего пути, но реализация не рискует переполнением при отрицании `Integer.MIN_VALUE`.

Критический путь нужен для расчёта минимального срока завершения связанных работ при неотрицательных длительностях. Вес пути конденсации описывает только переходы между SCC, не длительности внутри компонент. Циклический блок задач сам по себе не становится исполнимым от сжатия в вершину; для реального расписания нужно устранить или отдельно интерпретировать цикл. В произвольном графе longest walk может быть бесконечным из-за положительного цикла, а longest simple path — NP-трудная задача.
